# Техническое задание: Внедрение сессионной аутентификации (JWT)

## Введение

Сейчас система работает без сохранения состояния (stateless). Клиент каждый раз отправляет логин и пароль заново при смене пароля или удалении аккаунта. Это неудобно и небезопасно — пароль передается по сети при каждом действии.

**Решение:** Внедрить сессионную аутентификацию на базе JWT-токенов. Пользователь вводит пароль один раз, получает токен (пропуск) и использует его для защищенных операций.

# 2. Требования к реализации

## 2.1. Серверная часть (Node.js)
1. **Установка:** Выполнить `npm install jsonwebtoken`.
2. **Конфигурация:** Задать секретный ключ `JWT_SECRET` и время жизни токена (15 минут).
3. **Выдача токена:** В `POST /login` при верном пароле генерировать JWT (содержащий `username`) и возвращать его в JSON-ответе в поле `token`.
4. **Middleware (Охранник):** Написать функцию `authenticateToken`, которая извлекает токен из заголовка `Authorization: Bearer <token>`, проверяет его подпись и срок действия. Если токен неверный — возвращает `403 Forbidden`.
5. **Защита эндпоинтов:** Поставить `authenticateToken` на `/change-password` и `/delete-account`. Логин теперь берется из токена (`req.user.username`), а не из тела запроса.

## 2.2. Клиентская часть (C++)
1. **Хранение:** Добавить в класс `AuthSystem` поле `std::string currentToken`.
2. **Сохранение:** В методе `login()` извлекать токен из ответа сервера и сохранять в `currentToken`.
3. **Отправка:** В классе `HttpClient` добавить передачу заголовка `Authorization: Bearer <currentToken>`.
4. **Использование:** В методах `changePassword()` и `deleteAccount()` убрать `username` из JSON и прикладывать токен.
5. **Выход:** При выходе (пункт 6 меню) очищать `currentToken` (устанавливать пустую строку).

# 3. Модель угроз

## 3.1. Перечень угроз и меры защиты

| Угроза | Как защищает JWT | Статус |
|--------|------------------|--------|
| **Подделка токена** | Токен защищен криптографической подписью (HMAC-SHA256). Без ключа `JWT_SECRET` изменить данные в токене невозможно. | Защищено |
| **Replay-атака (Повтор)** | Токен имеет ограниченный срок жизни (15 минут). | ⚠️ Частично |
| **Кража токена с устройства** | Токен хранится только в оперативной памяти клиента, не пишется на диск. При закрытии программы уничтожается. | Защищено |
| **Использование токена после выхода** | Клиент стирает токен при выходе. Сервер не знает об этом, пока не истечет срок действия. | Частично |

## 3.2. Остаточные риски (ограничения системы)
1. **Отсутствие HTTPS:** Токен передается по сети в открытом виде. Злоумышленник с доступом к сети может перехватить его и выдать себя за пользователя в течение 15 минут.
2. **Отсутствие Blacklist (Черного списка):** Если пользователь нажал «Выйти», токен удаляется у клиента, но на сервере остается валидным до истечения 15 минут. Для мгновенного отзыва нужна база отозванных токенов.

# Чек-лист внедрения JWT (Сессии)

## Сервер (Node.js)
- [ ] **Установить библиотеку `jsonwebtoken`** (`npm install jsonwebtoken`). 
  
  *Зачем:* Чтобы сервер умел делать токены.
- [ ] **Задать `JWT_SECRET`** (секретный ключ).
  
  *Зачем:* Чтобы токен нельзя было подделать.
- [ ] **В `/login` выдавать токен**.
  
  *Зачем:* Чтобы пользователь получил «пропуск» после ввода пароля.
- [ ] **Проверять токен** (Middleware `authenticateToken`) в `/change-password` и `/delete-account`.
  
  *Зачем:* Чтобы сервер пускал только тех, у кого есть правильный токен, и сам знал, кто это.

## Клиент (C++)
- [ ] **Хранить токен в памяти** (`std::string currentToken`).
  
  *Зачем:* Чтобы клиенту было где его держать.
- [ ] **Сохранять токен после входа** (в методе `login`).
  
  *Зачем:* Чтобы потом им пользоваться.
- [ ] **Отправлять токен на сервер** (добавить заголовок `Authorization: Bearer ...`).
  
  *Зачем:* Чтобы сервер узнал клиента и не выдал ошибку 403.
- [ ] **Стирать токен при выходе** (пункт 6).
  
  *Зачем:* Чтобы после закрытия программы никто не зашел под твоим аккаунтом.

## Безопасность
- **Защищено:** Токен нельзя подделать, и он не сохраняется на диск.
- **Уязвимо:** Нет HTTPS (токен могут перехватить) и нет «черного списка» (после выхода токен на сервере живет 15 минут).
