# Клиент-серверная система аутентификации

Клиент-серверная система аутентификации с хешированием паролей через **Argon2id** и сессиями на базе **JWT-токенов** (Access + Refresh).

Проект состоит из двух частей:
- **`cpp/`** — консольный клиент на C++ (WinHTTP, JWT).
- **`server/`** — HTTP-сервер на Node.js (Express, SQLite, Argon2id, JWT).

## Архитектура

1. Пользователь вводит логин и пароль.
2. Клиент отправляет `POST /login` (JSON + nonce).
3. Сервер проверяет пароль (Argon2id) и выдаёт два токена: Access (15 мин) и Refresh (7 дней).
4. Клиент сохраняет токены (в памяти + зашифрованный файл `tokens.dat`) и передаёт Access-токен в заголовке `Authorization: Bearer <token>` при последующих запросах (смена пароля, удаление).
5. Если Access-токен истек, клиент автоматически обновляет его через `POST /refresh`.
6. При выходе токены удаляются из памяти и с диска, а на сервере Access-токен попадает в Blacklist.

Клиент **не хранит** пароли в открытом виде и **не работает с БД напрямую**. Клиент только собирает данные, шлёт HTTP-запросы и показывает ответы.

## Возможности

- **Регистрация и вход** пользователей.
- **Хеширование паролей Argon2id** (пакет `argon2` на сервере).
- **Проверка качества пароля** на клиенте (клавиатурные паттерны, года, повторы, короткие логины).
- **Блокировка аккаунта** после 3 неудачных попыток на 30 секунд.
- **Защита от replay-атак**: клиент передаёт `timestamp` и `nonce`, сервер проверяет их свежесть и уникальность.
- **JWT-сессии**: выдача Access (15 минут) и Refresh (7 дней) токенов.
- **Автообновление токена**: если Access истекает, клиент сам запрашивает новый по Refresh.
- **Защита от использования после выхода**: Access-токен добавляется в Blacklist (таблица в SQLite).
- **Локальное сохранение сессии**: токены хранятся в зашифрованном файле `tokens.dat`, чтобы при перезапуске программы не вводить пароль заново.
- **Смена пароля** и **удаление аккаунта** (по токену, без повторного ввода логина).


## Использование

Меню клиента:
```text
СИСТЕМА АУТЕНТИФИКАЦИИ
1. Вход
2. Регистрация
3. Сменить пароль
4. Удалить аккаунт
5. Список
6. Выход
```

- **Вход.** Отправляет логин, пароль, `timestamp` и `nonce`. Сервер проверяет данные и блокировку, после чего выдаёт токены.
- **Смена пароля/Удаление.** Используют Access-токен. Если токен истек, клиент автоматически использует Refresh-токен для получения новой пары.

## Модель угроз

Что защищаем:
- **сессии пользователей** — Access и Refresh токены;
- **целостность токенов** — данные внутри токена нельзя подделать;
- **локальное хранилище токенов** — файл `tokens.dat` зашифрован.

От кого:
- **нарушитель A (наблюдатель канала)** — перехват и повтор запроса с токеном.
  Защита: `timestamp` + `nonce` (защита от replay-атак).
- **нарушитель B (подделка токена)** — попытка изменить логин или срок действия в JWT.
  Защита: подпись HMAC-SHA256.
- **нарушитель C (кража Access-токена)** — перехват короткоживущего токена.
  Защита: короткий срок жизни (15 минут).
- **нарушитель D (кража Refresh-токена)** — перехват долгоживущего токена.
  Защита: хранение в БД с ротацией (при обновлении старый токен удаляется).
- **нарушитель E (использование токена после выхода)** — попытка воспользоваться токеном после Logout.
  Защита: добавление токена в Blacklist (таблица в SQLite).
- **нарушитель F (кража файла с токенами с диска)** — доступ к файлу `tokens.dat`.
  Защита: файл зашифрован (AES-256).

Что **не защищаем**:
- **долгое хранение старых токенов** — таблицы `blacklist` и `refresh_tokens` не чистятся автоматически, что засоряет БД.
