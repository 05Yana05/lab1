# Клиент-серверная система аутентификации

Клиент-серверная система аутентификации пользователей с хешированием паролей через **Argon2id** и защитой от **replay-атак**.

Проект состоит из двух частей:

- **`cpp/`** — консольный клиент на C++ (WinHTTP, JSON, Catch2-тесты).
- **`server/`** — HTTP-сервер на Node.js (Express, SQLite, Argon2id).

## Архитектура

```
┌───────────────────────┐   HTTP (JSON)   ┌───────────────────────┐
│  C++ клиент           │ ──────────────► │  Node.js сервер       │
│  Lab_1KB.exe          │                 │  localhost:3000       │
│                       │                 │                       │
│  HttpClient           │ ◄────────────── │  express              │
│  JsonHelper           │   JSON-ответ    │  argon2               │
│  AuthSystem           │                 │  better-sqlite3       │
│  Validator            │                 │  users.db (SQLite)    │
└───────────────────────┘                 └───────────────────────┘
```

Клиент **не хранит** пароли и **не работает с БД**. Всё это — на сервере. Клиент только собирает данные, шлёт HTTP-запросы и показывает ответы.

## Возможности

- **Регистрация и вход** пользователей.
- **Хеширование паролей Argon2id** (пакет `argon2` на сервере, RFC 9106).
- **Проверка качества пароля** на клиенте:
  - отсечение 1000 частых паролей (файл `top1000.txt`);
  - запрет клавиатурных последовательностей (`qwerty`, `asdf`, `zxcvbn`);
  - запрет трёх одинаковых символов подряд (`aaa`, `111`);
  - запрет года в пароле (`1990`–`2099`);
  - корректный подсчёт Unicode-символов (кириллица, эмодзи).
- **Блокировка аккаунта** после 3 неудачных попыток на 30 секунд.
- **Защита от replay-атак**: клиент передаёт `timestamp` и `nonce`, сервер проверяет свежесть метки и уникальность nonce.
- **Смена пароля** и **удаление аккаунта** через сервер.
- **Юнит-тесты** на C++ через Catch2 — 15 тестов, 34 проверки.

## Сборка и запуск

### 1. Сервер (Node.js)

```bash
cd server
npm install
node server.js
```

Ожидаемый вывод:

```
База данных готова: users.db
Сервер запущен: http://localhost:3000
Готов принимать запросы.
```

**Оставь это окно открытым.**

### 2. Клиент (C++)

1. Открой `cpp/Lab_1KB.sln` в Visual Studio 2022.
2. В свойствах проекта пропиши пути к libsodium:
   - **C/C++ → Общие → Дополнительные каталоги включаемых файлов:**
     `D:\libsodium\libsodium\include`
   - **Компоновщик → Общие → Дополнительные каталоги библиотек:**
     `D:\libsodium\libsodium\x64\Release\v143\static`
   - **Компоновщик → Ввод → Дополнительные зависимости:** `libsodium.lib`
   - **C/C++ → Препроцессор → Определения препроцессора:** `SODIUM_STATIC`
   - **C/C++ → Командная строка → Дополнительные параметры:** `/utf-8`
3. Убедись, что файл `cpp/top1000.txt` копируется рядом с `.exe`.
4. Собери решение (**Ctrl+Shift+B**).
5. Запусти (**Ctrl+F5**) — при условии, что сервер уже работает.

## Использование

Меню клиента:

```
СИСТЕМА АУТЕНТИФИКАЦИИ
1. Вход в систему
2. Регистрация
3. Сменить пароль
4. Удалить аккаунт
5. Показать всех пользователей
6. Выход
```

**Регистрация.** Логин от 3 символов Unicode, пароль без ограничений
сложности (но проверяется на слабость). При успехе пароль хешируется
на сервере Argon2id и сохраняется в SQLite.

**Вход.** Логин, пароль, `timestamp` и `nonce` уходят на сервер.
Сервер проверяет:
- `timestamp` не старше 30 секунд;
- `nonce` не использовался ранее;
- пароль через `argon2.verify`;
- аккаунт не заблокирован.

После 3 неудачных попыток аккаунт блокируется на 30 секунд.

## Юнит-тесты

Тесты на C++ через **Catch2**:

```
===============================================================================
All tests passed (34 assertions in 15 test cases)
```

Покрывают:
- `Validator::validateUsername` — проверка логина;
- `Validator::validatePassword` — проверка пароля;
- `Validator::utf8_length` — подсчёт Unicode-символов;
- `Hash::hashPassword` / `Hash::verifyPassword` — хеширование.

## Модель угроз

Что защищаем:
- **пароли пользователей** — хранятся только как Argon2id-хеши;
- **целостность данных** — SQLite на сервере;
- **доступность** — блокировка после 3 попыток.

От кого:
- **нарушитель A (наблюдатель канала)** — перехват и повтор запроса.
  Защита: `timestamp` + `nonce` (защита от replay).
- **нарушитель B (кража БД)** — подбор паролей офлайн.
  Защита: Argon2id с 64 МБ памяти.
- **нарушитель C (подбор через UI)** — перебор паролей.
  Защита: блокировка + проверка качества паролей.

Что **не защищаем**:
- **пароль передаётся по HTTP в открытом виде** — в реальной системе нужен HTTPS или challenge-response;
- **SQL-инъекции** в устаревшем `Database.cpp` — файл не используется, но если вернуть в сборку, уязвимость вернётся;

## Известные ограничения

- Пароль летит по HTTP в открытом виде. **Нужен TLS**.
- Нет rate-limiting по частоте запросов.
