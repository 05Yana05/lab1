# Система аутентификации

Консольное приложение на C++ с аутентификацией пользователей, хешированием паролей через Argon2.

## Возможности

- **Регистрация и вход** пользователей через консольное меню.
- **Хеширование паролей Argon2** через библиотеку libsodium.
- **Проверка качества пароля** при регистрации и смене:
  - отсечение 1000 самых частых паролей;
  - запрет клавиатурных последовательностей (`qwerty`, `zxcvbn`, `1234`, `asdf`);
  - запрет трёх одинаковых символов подряд (`aaa`, `111`, `!!!`) через regex;
  - запрет года (1900–2099) в пароле через regex.
- **Блокировка аккаунта** после 3 неудачных попыток входа на 30 секунд.
- **Защита от replay-атак**: клиент передаёт `timestamp` и `nonce`, «сервер» проверяет свежесть метки времени и уникальность nonce.
- **Логирование** событий аутентификации в файл `auth.log` с временными метками.
- **UTF-8** — работа с кириллицей и эмодзи.

## Сборка

1. **Скачайте libsodium.**
   Файл `libsodium-1.0.22-stable-msvc.zip` .
   Распакуйте в папку, например:
   ```
   D:\libsodium\
   ```

2. **Откройте проект** `Lab_1KB.sln` в Visual Studio 2022.

3. **Настройте свойства проекта** (правой кнопкой по проекту `Lab_1KB` → **Свойства**).
   Вверху выбери:
   - **Конфигурация:** `Все конфигурации`
   - **Платформа:** `x64`

   Затем пропишите:

   | Раздел | Параметр | Значение |
   |---|---|---|
   | C/C++ → Общие | Дополнительные каталоги включаемых файлов | `D:\libsodium\libsodium\include` |
   | Компоновщик → Общие | Дополнительные каталоги библиотек | `D:\libsodium\libsodium\x64\Release\v143\static` |
   | Компоновщик → Ввод | Дополнительные зависимости | `libsodium.lib` |
   | C/C++ → Препроцессор | Определения препроцессора | `SODIUM_STATIC` |
   | C/C++ → Командная строка | Дополнительные параметры | `/utf-8` |

4. **Проверьте `top1000.txt`.**
   Файл должен лежать в папке проекта (`Lab_1KB\Lab_1KB\top1000.txt`).

5. **Соберите и запустите решение.**

## Использование

После запуска появится меню:

```
СИСТЕМА АУТЕНТИФИКАЦИИ
1. Вход в систему
2. Регистрация
3. Сменить пароль
4. Удалить аккаунт
5. Показать всех пользователей
6. Выход
```

### Основные сценарии

**Регистрация.** Введи логин (минимум 3 символа Unicode) и пароль дважды. Пароль проверяется на частые значения, клавиатурные последовательности, повторяющиеся символы, год. При успехе пароль хешируется Argon2 и сохраняется в БД.

**Вход.** Введи логин и пароль. В консоль выводятся отладочные сообщения о проверке `timestamp` и `nonce`:

```
[СЕРВЕР] Получен пакет: username=alice, timestamp=1712345678, nonce=a1b2c3d4e5f60718
```

После 3 неудачных попыток аккаунт блокируется на 30 секунд.

**Смена пароля.** Требуется старый пароль и новый. Новый проверяется так же, как при регистрации.

**Удаление аккаунта.** Требуется пароль для подтверждения и ввод `y`.

**Показать всех пользователей.** Выводится список логинов со счётчиком неудачных попыток и статусом блокировки. Пароли и хеши не выводятся.

## Логи

Все события пишутся в файл `auth.log` рядом с `.exe`.
Формат:

```
[2026-09-17 14:23:01] REGISTER OK: username=alice
[2026-09-17 14:23:15] LOGIN OK: username=alice
[2026-09-17 14:23:30] LOGIN FAIL: username=alice, reason=wrong password, attempt=1
[2026-09-17 14:23:40] ACCOUNT LOCKED: username=alice, duration=30s
```

Типы событий: `REGISTER OK`, `LOGIN OK`, `LOGIN FAIL`, `ACCOUNT LOCKED`, `PASSWORD CHANGED`, `ACCOUNT DELETED`, `REPLAY DETECTED`.

## Хранение данных

**Файл `users.db`** — база SQLite. Создаётся автоматически при первом запуске.

Таблица `users`:

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | Автоинкремент |
| `username` | TEXT UNIQUE | Логин |
| `password_hash` | TEXT | PHC-строка Argon2 |
| `failed_attempts` | INTEGER | Счётчик неудачных попыток |
| `lock_until` | INTEGER | Время разблокировки (Unix time) |

Таблица `common_passwords`:

| Поле | Тип | Описание |
|---|---|---|
| `password` | TEXT PRIMARY KEY | Частый пароль из `top1000.txt` |

## Модель угроз

### Что защищаем

| Защищаем | Где хранится | Почему важен |
|---|---|---|
| Пароли пользователей | Таблица `users`, колонка `password_hash` | Утечка даёт доступ к аккаунтам |
| Целостность БД | Файл `users.db` | Нельзя изменить пользователя в обход системы |

### От кого защищаем

**Нарушитель A. Внешний наблюдатель канала.**
Читает весь трафик между клиентом и сервером, может сохранять пакеты для повторной отправки. Не может изменять трафик, читать БД или выполнять код на сервере.

*Что защищаем:* replay-атаки — «сервер» проверяет `timestamp` (не старше 30 секунд) и `nonce` (не должен использоваться дважды).

**Нарушитель B. Локальный нарушитель с доступом к БД.**
Украл файл `users.db`, изучает содержимое офлайн.

*Что защищаем:* пароли хранятся как PHC-строки Argon2 — перебор требует больших ресурсов CPU и памяти (~64 МБ на попытку). Соль встроена в PHC-строку и уникальна для каждого пользователя.

**Нарушитель C. Пользователь, подбирающий пароль.**
Отправляет запросы через консольное меню.

*Что защищаем:* проверка качества пароля при регистрации и смене (частые пароли, клавиатурные последовательности, повторяющиеся символы, год), блокировка аккаунта после 3 неудачных попыток на 30 секунд.
